## 用户需求原文

> 我建议直接做一个知识库，这个知识库只需要补充信息即可，举个例子：
> 1. tesla在1月1日有一条新闻，那么tesla的知识库时间轴就有了1/1的一个节点，这个节点展开的对应分类有当天的新闻。
> 2. 假设1月1日特斯拉有两个分类的新闻，那么1/1的节点就可以展开两个分类，再展开两个分类的新闻。
>
> 网站有一个不同于新闻分类的模块，叫做知识库，或者历史信息。这个知识库有人物（比如马斯克）、重大事件（比如俄乌战争）、公司（比如特斯拉）的时间轴，这个时间轴首先应该有一些最核心的节点（一些公认的重要节点），在这个时间轴上，其他的节点就是我们抓取的新闻了。
>
> 附加功能：
> - 简报里面点击超链接直接跳转到对应"人物""事件""公司"的知识库
> - 语音功能：让语音讲解这个"名词"的历史是什么

---

## 核心理解

这是一个**实体知识图谱系统**，而不是简单的实体背景卡片。

**核心概念**：
- 每个实体（人物/公司/事件）有独立的**知识库页面**
- 页面核心是**时间轴**，由两部分组成：
  1. **基础节点**：公认的历史里程碑（AI预置）
  2. **动态节点**：系统抓取的新闻自动追加
- 新闻简报中的实体名称变成**超链接**，点击跳转知识库

## 数据模型设计

### Entity（实体知识库）

```javascript
const entitySchema = new mongoose.Schema({
  name: { type: String, required: true, unique: true },  // 特斯拉
  aliases: [String],  // ["Tesla", "TSLA"]
  type: {
    type: String,
    enum: ['company', 'person', 'event', 'concept'],
    required: true
  },
  description: String,  // 一段话介绍
  image: String,  // 头像/Logo URL
  metadata: {
    founded: String,      // 公司成立时间
    founder: String,      // 创始人
    headquarters: String, // 总部
    // ... 其他元数据
  },
  base_timeline: [{  // AI生成的基础历史节点
    date: String,      // "2003" 或 "2008.02"
    event: String,     // 事件描述
    importance: { type: String, enum: ['milestone', 'major', 'normal'] }
  }],
  news_count: { type: Number, default: 0 },  // 关联新闻数量
  last_news_at: Date,  // 最近新闻时间
  created_at: { type: Date, default: Date.now },
  updated_at: { type: Date, default: Date.now }
});
```

### EntityNews（实体-新闻关联）

```javascript
const entityNewsSchema = new mongoose.Schema({
  entity_id: { type: mongoose.Schema.Types.ObjectId, ref: 'Entity', required: true },
  brief_id: { type: mongoose.Schema.Types.ObjectId, ref: 'Brief', required: true },
  date: String,  // "2025-01-15"
  category: String,  // "automotive"
  relevance: String,  // "特斯拉发布FSD v13" - 这条新闻与实体的关系
  created_at: { type: Date, default: Date.now }
});
```

## 工作流程

### 1. 实体识别与关联（AI处理时）

修改prompt，在处理新闻时识别关联实体：

```python
"entity_mentions": [
  { "name": "特斯拉", "type": "company", "relevance": "发布FSD v13" },
  { "name": "马斯克", "type": "person", "relevance": "宣布量产计划" }
]
```

### 2. 实体自动创建/更新

```
新闻处理流程：
1. AI返回 entity_mentions
2. 查询Entity集合，检查实体是否存在
   - 存在 → 创建 EntityNews 关联
   - 不存在 → 判断是否值得创建新实体
     - 高频出现（>3次）或 重要性高 → 创建新实体 + 调用AI生成基础时间轴
     - 否则 → 仅记录mention，暂不创建
3. 更新 Entity.news_count 和 last_news_at
```

### 3. 基础时间轴生成（一次性）

```python
# 单独的prompt，仅在创建新实体时调用
ENTITY_TIMELINE_PROMPT = """
为以下实体生成历史时间轴（5-10个关键节点）：
实体名称: {name}
实体类型: {type}

要求：
- 只包含公认的、可查证的重大事件
- 时间格式: YYYY.MM 或 YYYY
- 按时间正序排列

输出JSON: { "description": "一段话介绍", "timeline": [{"date": "...", "event": "..."}] }
"""
```

## Token成本分析

| 场景 | 调用时机 | Token消耗 | 频率 |
|------|---------|----------|------|
| 新闻处理识别实体 | 每条新闻 | +50-80 | 高 |
| 创建新实体基础时间轴 | 新实体首次创建 | ~300-500 | 低（每周几个） |
| **总增长** | | **约10-15%** | |

### 优化策略

1. 实体识别复用现有 `entities` 字段逻辑，改为输出 `entity_mentions`
2. 高频实体（特斯拉/苹果等）预置到数据库，不需要AI生成
3. 冷门实体达到阈值（出现3次以上）才创建知识库页面

## 技术要点

### 稳定性保障
1. **渐进式上线**：先预置热门实体，验证稳定后开启自动创建
2. **独立集合**：Entity和Brief完全解耦，不影响现有新闻流程
3. **降级策略**：实体API失败时，新闻简报正常显示（无链接）

### 与现有功能的关系
- **话题聚合**：话题=短期事件聚合，实体=长期知识沉淀（互补）
- **entities字段**：改为 entity_mentions，同时输出到简报展示和知识库关联
- **TTS**：复用现有豆包语音服务

|------|------|------|
